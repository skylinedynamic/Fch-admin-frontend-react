# BUG-165 / BUG-170 retest fixes (10-Nov-26)

## BUG-165 — Employee create after buying a seat stayed on /employees/create
**Problem:** Add Employee + Create account with no free seat → buy seat → Save → payment window. After paying, `handlePaymentSuccess` ran `window.location.reload()`, so the page reloaded `/employees/create` with an empty form.
**Solution:** The created employee's id is kept (`createdEmployeeId`). Paying, or closing the payment window unpaid (the employee already exists), now navigates to `/employee-details/{id}` (or `/employees` if no id came back). The no-purchase path was already correct.

## BUG-170 — Sidebar logo fallback name unreadable
**Problem:** When the sidebar logo fails, `BrandLogo` shows the site name, but it inherited the logo link colour `#405189` on the navy sidebar `#001f3f` (~2.2:1).
**Solution:** `.app-menu .navbar-brand-box .brand-logo-text` now uses `var(--brand-on-sidebar)` (default `#d3d8e5`, ~11:1 on `#001f3f`; per-tenant value comes from `brandingTheme.ts`). Covers both the wide logo and the collapsed-menu initial.
